# T03 결과 — 검토 대기

담당: 위임된 구현 에이전트, 환경 기본 모델/추론 설정 사용. 별도 모델 또는 effort override를 설정하지 않았다. 코드 편집 범위는 `mods/codenav/everywhere.js`, `run.js`, `http.js`, `termfiles.js`다.

## 변경

- 검색 전체·최근 파일·파일 구조·줄 이동과 터미널 파일 선택기에 공통 `popupSurface`, UI 글꼴과 크기 배율, 24px 결과 행, 28px 입력 컨트롤을 적용했다. 자식 배경이 외곽 모서리에 닿지 않도록 표면 안쪽 4px 여백을 둔다.
- 실행 구성 메뉴와 HTTP 환경 메뉴에 공통 팝업 표면, 둥근 선택 행, UI 글꼴과 배율을 적용했다. 현재 항목에서 시작하는 키보드 포커스와 위/아래/Enter/Esc 처리를 추가했다. 빈 HTTP 환경에서 Enter는 아무 값도 저장하지 않는다.
- 실행 구성 편집기에 공통 다이얼로그 표면과 4px 안쪽 여백, 공통 입력·버튼·트리 행 크기를 적용했다. idea에서는 첫 필드 또는 빈 다이얼로그에 포커스를 주고 Enter로 OK, Esc로 취소한다. 기존 Apply/Run/Cancel 버튼과 저장 방식은 유지한다.
- HTTP 파일 머리줄은 idea 섬 표면과 공통 머리줄 높이/UI 글꼴을 사용한다.
- 터미널 컨텍스트 메뉴에 공통 표면·행·선택 모서리를 적용하고 처리한 키의 전파를 멈춘다. 터미널 파일 선택기에서 빈 목록에 아래 키를 눌러 음수 선택 인덱스가 되던 경계를 보완했다.
- codebench의 기존 표면·행 크기·글꼴 크기는 `isIdea` 분기 및 `uiSize`의 비-idea 동작을 통해 유지한다. 실행 명령, HTTP 요청 파싱/환경/비밀값/globals 처리, 터미널 경로 해석과 클립보드 처리, 키맵은 변경하지 않았다.

## 검증 근거

실행한 검사:

- 변경한 JS 네 파일 각각 `node --check`: 모두 통과.
- `git diff --check`: 통과.

코드 검토:

- `mods/codenav/gpui-kit.d.ts`의 `focus_handle`, `track_focus`, `on_key_down`, 전파 규칙을 확인해 기존 Input 포커스와 별개로 대화상자/목록 루트에 포커스 경로를 등록했다.
- 기존 실행 구성 선택·저장·실행 함수와 HTTP 환경 저장은 같은 함수를 호출하며, Enter는 클릭과 같은 선택 경로를 사용한다.
- 로딩·빈 목록·오류 문구는 동일한 표면과 안쪽 여백 안에 렌더링된다. 정보와 오류를 대체하거나 성공 응답을 만들지 않았다.

## 미확인 및 후속

앱 설치·Herdr CLI·화면 조작은 태스크 경계에 따라 실행하지 않았다. 따라서 실제 모서리 렌더링, 폰트 크기 설정 변경, 입력 포커스의 키 전달, 스크롤 밖 선택 행 표시, Enter/Esc의 앱 통합 동작은 상위 에이전트의 화면 검증이 필요하다. UI 구조·데이터 계약의 소스 검토 및 문법 검사는 통과했으나 R01/R02/R04의 화면 수용 기준 전체 충족으로 보고하지 않는다.
