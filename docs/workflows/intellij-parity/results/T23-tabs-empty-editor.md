# T23 탭 닫기·활성 탭 노출·빈 에디터

사용자가 보고한 ClientAuthApplication.kt는 현재 파일로 등록돼 있었으나, 열린 10개 탭 중 9번째 항목이 탭 줄 바깥에 가려져 있었다. 공통 TabViewport/uiTabStrip을 추가해 실제 탭 폭과 뷰포트 폭으로 활성 항목을 노출한다. 탭 순서는 유지하며 일반 redraw는 수동 휠 위치를 유지한다. 닫기/가운데 클릭/우클릭을 위해 일반 element를 그대로 사용한다.

탭 상태 등록과 스택 라우팅은 항상 보이는 Status로 옮겼다. 지연 등록은 실행 시 파일/리뷰와 스페이스를 다시 검사해 닫힌 파일을 되살리지 않게 한다. 오래된 탭 클릭도 닫힌 항목을 다시 열 수 없다. 코드 읽기가 대기 중이면 파일 닫기 후 무효화한다. 리뷰 publication과 읽기에서도 스페이스·저장소 경계를 확인한다. 탐색기에서 파일을 열면 리뷰 모드를 종료한다.

IDEA의 마지막 탭을 닫으면 editor-area를 유지하고 탭 줄만 숨긴 뒤 code child의 빈 화면을 표시한다. 공통 uiEmptyEditor는 에디터 배경 위에 회색 검색/파일 이동/최근 파일/Project 단축키와 드롭 안내를 가운데 배치한다. 지원하지 않는 Navigation Bar 대신 실제 동작하는 Project 단축키를 표시한다. codebench의 마지막 탭 닫기 동작은 유지한다.

검증: check_tabs VM(마지막 탭·전체 닫기·옆 탭 선택·지연 등록 무효화·다른 스페이스/저장소 리뷰·숨겨진 탭 줄 복귀·codebench), check_system(활성 탭 가시성·리사이즈·수동 휠 보존 포함), generator drift, 두 모드 native check 통과. 실제 CU에서 ClientAuthApplication.kt가 선택 상태로 탭 줄 안에 노출된 것을 확인했다. 기존 프로젝트 탭을 유지한 채 홈 스페이스에서 문서 한 개 열기→마지막 X 닫기→빈 화면, 숨겨진 줄에서 파일 재열기까지 확인했다. 최종 런타임 재시작 후 같은 왕복을 확인하고 원래 프로젝트로 돌아왔다. 전체 닫기의 비동기 경쟁은 VM으로 검사했으며 실제 프로젝트의 탭 전체를 다시 닫아 검증하지는 않았다.
